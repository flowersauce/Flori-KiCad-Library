# 旧库兼容层

新工作使用 `PCM_Flori_*` 主库。本目录在重新分类后继续支持
`Flowersauce_*` 和 `PCM_Flowersauce_*` 历史库 ID。

PCM 包会从主库即时生成旧库定义；安装后的旧昵称与历史资源配置方式见
[PCM 安装说明](../pcm/INSTALL_zh.md#旧工程兼容配置按需)。

## 生成的库定义

- `symbols/`：3 个聚合库，包含迁移时的 35 个符号。
- `footprints/`：4 个聚合库，包含迁移时的 53 个封装。
- [library-layout.json](../tools/library-layout.json)：历史成员映射和新旧资源路径映射。

这些定义由 `Flori_*` 主库生成，并随 Git 保存。
已有工程可继续通过旧 ID 查找，但编辑时应打开对应主库。
直接修改本目录中的生成文件，会在下次刷新时被覆盖。

修改带历史映射的主库器件后，在仓库根目录运行：

```powershell
python tools/sync_compat.py
```

将变化的生成定义与主库源文件一起提交。
新增器件只加入主库；旧别名覆盖迁移时记录的成员。
重命名或移除已映射器件时，需要明确调整兼容映射，不能只删除主库中的定义。

## 本地资源路径兼容

`compat/3dmodels/` 和 `compat/resources/` 在本机生成，由 Git 忽略。
刷新时优先使用硬链接，不支持时退回文件复制。
这些文件按只读使用：硬链接与主资源共享内容，编辑它也可能改动主资源。

设备配置将 `FLOWERSAUCE_KICAD_DIR` 指向本目录，以解析旧的模型和手册变量路径；
`FLORI_KICAD_DIR` 指向仓库根目录，供新引用使用。
如果已有工程仍使用旧路径，在拉取资源更新后运行刷新脚本，因为 Git 可能替换了原先被链接的文件。

此兼容层保留已注册的库 ID 和历史变量路径。
工程库表若直接写了已移除目录的绝对路径，仍可能需要一次路径更新。
需要迁移工程内缓存定义时，使用 KiCad 的库更新或封装替换工具。

首次注册见[开发维护流程](../docs/development-workflow.md)。
当前 ID 与路径映射见[Flori 迁移记录](../docs/audits/flori-migration-2026-11-04.json)。
